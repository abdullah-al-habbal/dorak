# Source layout

Architecture rules for the dashboard. All imports use the `@/` alias; never `./` or `../` (ESLint `no-restricted-imports` fails the build on a relative import). Exported components in `components/` (outside `ui/`) declare their return type (`explicit-module-boundary-types`).

"One per file" below means one **domain concept** per file: split by concept, not by line count. Closely related declarations that change together (the types of one entity, a CRUD hook bundle for one entity) may share a file. Do not mass-merge or mass-split existing files.

| Folder | Rule |
| --- | --- |
| `interfaces/` | One interface (or one tight group for a concept) per file, `<name>.interface.ts`, grouped in `interfaces/<domain>/` (`core/{query,transport}` and `ui/{data,shell}` for shared). |
| `types/` | One type (or the types of one entity) per file, `<name>.type.ts`, grouped in `types/<domain>/` (`core/{session,forms,api,shared}` and `account/{profile,forms}` split by concern). |
| `schemas/` | One Zod schema (or the schemas of one entity) per file, `<name>.zod.ts`, grouped in `schemas/<domain>/` (`core/{session,api}` for envelopes, session and locale; `account/{account,credentials,register}`). |
| `schemas/fields/` | Zod field builders for shared form rules (`nameField`, `emailField`, `phoneField`, `passwordField`). Form schemas compose these instead of repeating the chain; limits live in `config/money-shell/field-limit.constant.ts` or the module's constant. |
| `enums/<group>/` | Explicit TypeScript enums for domain modes and categories, grouped `access`, `booking`, `venue`, `people`, `money`, `ui`. |
| `components/` | No flat files. Group into typed subfolders (`buttons/`, `forms/`, `dialogs/`, `layout/`, shadcn `ui/`). |
| `services/api/query/<domain>/` | Read-only API actions (TanStack Query), grouped by domain (`core` for session). |
| `services/api/mutation/<domain>/` | Write API actions (TanStack mutations), grouped by domain (`core` for login and logout). |
| `store/` | Zustand client state (theme, auth profile). Layout state that needs server seeding lives in providers instead. |
| `components/providers/` | App-wide and portal context providers (`SidebarProvider`, `I18nProvider`, `AppProviders`). |
| `components/overlays/` | `OverlayProvider` and the single dialog/sheet host. Add a kind to `OverlayKind` and `OverlayRequest`, then a case in `OverlayHost`. |
| `lib/` | Shared helpers. `utils.ts`, `api-response.ts`, `parse-guard.ts` and `query-client.ts` stay at the root (`utils.ts` is generated by shadcn); `.util.ts` files are grouped in `lib/<domain>/` (`lib/core/{format,query,errors}` for shared formatting, money, url and mutation helpers). Tests mirror the folders. |
| `lib/query-keys/<domain>/` | One `<name>-keys.ts` query-key factory per module, grouped by domain (bookings, branches, stylists, services, chairs, hours, earnings, clients, plans, brands, account, platform, jobs). Domain map: `.claude/skills/dashboard-folder-decoupler/references/domain-map.md`. |
| `lib/core/errors/map-api-form-error.util.ts` | `mapApiFormError(error, generic, toFormFieldName?)` turns a failed write into a `MappedFormError` (`interfaces/core/query/mapped-form-error.interface.ts`). Module mappers (plan, branch, platform settings) pass their own field-name mapper and keep only their status-specific cases. `formErrorMessage(error, generic)` reduces it to one message (first field error, else the form-level one) for forms with a single error slot, such as the inline service category form and the working-hours banner. |
| `config/` | `*.constant.ts` files. Runtime and frozen constants (actors, routes, cookies, backend, locales, proxy allow-list, stale time, theme) stay at the root; the rest is grouped in `config/{platform,ops,venue,money-shell}/`. |
| `locales/` | Typed EN and AR dictionaries, split by namespace, plus locale resolution. |
| `hooks/` | One hook per file, named `use-<name>.ts`; a CRUD hook bundle for one entity may share a file, grouped in `hooks/<domain>/`; large domains split again (`core/{query,state,forms}`, `stylists/{approvals,invite,roster}`, `platform/{admin-users,currencies,settings}`, `services/{catalog,services}`, `brands/{admin,owner}`, `clients/{clients,reviews}`, `plans/subscriptions`, `account/notifications`, `branches/invitations`). Shared primitives and providers' hooks (`use-dictionary`, `use-i18n`, `use-overlay`, `use-list-query`, ...) live in `hooks/core/`. The shared-primitive rows below name files without the folder. |
| `hooks/core/query/use-optimistic-toggle-mutation.ts` | `useOptimisticToggleMutation({ queryKey, mutationFn, patch, successMessage, failureMessage? })` for switch toggles: cancels and snapshots every cached entry under `queryKey`, applies `patch` to each, restores the snapshots on failure (toasting `failureMessage` when given), toasts success, then invalidates the root plus any extra roots passed as `invalidate`. The callbacks live in `lib/core/query/optimistic-toggle-mutation.util.ts` so they are unit-tested without React. Used by the stylist status, service active and chair status hooks. |
| `hooks/core/query/use-feedback-mutation.ts` | `useFeedbackMutation({ mutationFn, invalidate, successMessage, errorMessage? })` for writes that toast and refresh: toasts `successMessage(data, variables)` on success, toasts `errorMessage(error)` on failure only when given (forms that show the backend reason inline leave it out), then invalidates every root in `invalidate` once settled, success or failure. The callbacks live in `lib/core/query/feedback-mutation.util.ts`. Used by the booking status, reschedule and walk-in hooks, the payout transition and generation hooks, the subscription status and assignment hooks, and platform settings. |
| `hooks/core/query/use-list-query.ts` | `useListQuery(queryKey, queryFn, enabled?)` for paged or filtered lists: wraps `useQuery` with `placeholderData: keepPreviousData`, so the previous page stays on screen (with `isPlaceholderData`) while the next key loads; `enabled` defaults to `true`. The options live in `lib/core/query/list-query.util.ts`. Used by the branches, stylists, chairs, services, plans, reviews, payouts, admin payouts, admin subscriptions, schedule appointments and bookings hooks. |
| `hooks/core/state/use-url-state.ts` | `useUrlState(fromParams, toParams)` keeps a value in the URL: it parses the current search params and writes a whole value back through `useReplaceQuery`. Pass stable serialisers (module functions, or `useCallback` when they need an argument such as `today`), so `setValue` keeps its identity; the services `SearchInput` lists its `onCommit` as an effect dependency. Used by `useEarningsRange`, `useServiceSearch` and `useUrlFilters`. |
| `hooks/core/state/use-url-filters.ts` | `useUrlFilters(fromParams, toParams)` for paged list filters: `useUrlState` plus `applyFilterPatch` (`lib/core/query/url-query.util.ts`), so any change other than `page` resets to page 1. Used by the booking, branch, chair, stylist, review, plan, payout, schedule and admin subscription filter hooks, whose page setter is the `PaginationBar`'s required `onPageChange`. |
| `hooks/core/query/use-replace-query.ts` | `useReplaceQuery()` returns the one writer for query strings: `router.replace` to `toReplaceHref(pathname, query)` (the bare pathname when the query is empty) with `{ scroll: false }`, so a filter change replaces the history entry instead of adding one. |
| `hooks/core/query/use-detail-query.ts` | `useDetailQuery(id, keyFor, fetcher, extras?)` reads one record by id: while `id` is `null` or `undefined` the `queryFn` is TanStack's `skipToken` (no request, the query stays idle), otherwise it fetches `fetcher(id)` under `keyFor(id ?? "")`; `extras.gcTime` sets the cache lifetime. The options live in `lib/core/query/detail-query.util.ts`. Used by `useBookingHistory`, `useOpeningHours` and `useBranchDetail`. |
| `hooks/bookings/use-bookings-query.ts` | `useBookingsQuery(filters, weekStart)` reads the bookings screen's data under `bookingKeys.list(filters)` through `useListQuery`. The fetch lives in `fetchBookingsForView` (`services/api/query/bookings/bookings.query.ts`): one page for the list view, the whole window as a single page (via `resolvePageInfo`) for the day and week grids. |
| `components/ui/skeleton-row.tsx` | `SkeletonRow({ className? })` is one full-width placeholder row whose shimmer stops under reduced motion; `SkeletonRows({ count, rowClassName?, className? })` stacks them inside one `role="status"` region labelled `common.loading`. `TableSkeleton`, the booking history timeline and the plan, branch and assign-subscription form dialogs use it; loading lists build on it instead of mapping `Skeleton` by hand. |
| `components/common/status-badge.tsx` | `StatusBadge({ status, styles, labels, scope })` renders icon plus text for a status. A status the style map or the dictionary lacks shows `common.unknown` and warns once per `scope:key` outside production; it never throws and never shows the raw key. Every `*-status-badge.tsx` passes its maps to it. |
| Density rule | Every `src/` folder holds at most 10 direct files; split a folder that grows past that into cohesive subfolders. Fewer files is fine. Exempt: `app/`, `components/ui/**`, `locales/**`, `services/api/auth`. Gate: `.claude/skills/dashboard-folder-decoupler/scripts/density.sh` and `verify-imports.mjs`. |
| `components/` splits | Large screens group into subfolders (`auth/{screens,forms}`, `branches/oversight`, `account/notifications`, `admin-brands/detail`, `bookings/dialogs`, `layout/notifications`). |
| `tests/` (project root) | Mirrors `src/`; import app code and helpers through `@/` and `@tests/`. |

## Routing

Paths are guard-segmented: `host/dashboard/<guardName>/...`, which maps to
`src/app/dashboard/[guard]/...`.

- `login/` is public. `(portal)/` is the signed-in shell and reads the session behind Suspense.
- `app/api/auth/*` (session) and `app/api/dashboard/[...path]` (the allow-listed data forwarder) are the only route handlers that talk to the backend.
- Guard names come from `AUTH_ACTORS` in `config/auth-actors.constant.ts`; never keep a second list.
